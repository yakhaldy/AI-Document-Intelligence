# Étape 4 — Stockage : ingestion + indexation vectorielle

Date : 2026-09-22
Méthode : `docker-compose up` (PostgreSQL 16 + pgvector), `alembic upgrade head`,
`python -m db.ingest`, `python -m db.index_chunks`.

## Résultat

| Table | Lignes |
|---|---|
| documents | 200 |
| invoices | 200 |
| suppliers | 40 (dédupliqués par ICE) |
| document_chunks | 995 (sur 85/200 documents) |

- **200/200 factures ingérées** (schéma + extraction Étape 2 réutilisée).
  9/200 (4.5%) en repli regex seul — l'extraction LLM (Gemini) a échoué sur
  ces documents (503/429 intermittents), loggé clairement, pas silencieux.
- **85/200 documents indexés en vecteurs** (995 chunks, `gemini-embedding-001`,
  1024 dimensions). Les 115 restants n'ont **pas** été indexés : le quota
  gratuit de l'API d'embedding a fini par être atteint (429 persistant en fin
  de deuxième passe) après plusieurs centaines d'appels cumulés dans la
  session (extraction + classification + embeddings). Le script
  (`db/index_chunks.py`) gère l'échec proprement (log + skip, pas de crash)
  et est ré-exécutable sans dupliquer ce qui existe déjà — il suffit de le
  relancer une fois le quota reconstitué pour compléter les 115 restants.

## Bug trouvé et corrigé en cours de route

`db/index_chunks.py` n'avait pas de repli gracieux sur échec d'embedding
(contrairement à `db/ingest.py` pour l'extraction) — un premier run a crashé
après seulement 11/200 documents sur une erreur 429 non interceptée. Corrigé
(try/except + log + skip), vérifié par un second run qui a bien continué
jusqu'au bout malgré de nouveaux 429 en fin de parcours.

## Limites connues (documentées, pas cachées)

- `documents.ocr_confidence`, `suppliers.city`, `invoices.payment_status` :
  laissés `NULL` — non extraits par le pipeline Étape 2, pas de valeur
  fabriquée pour les remplir.
- `invoice_lines` : table vide — l'extraction de lignes de facture n'est pas
  implémentée (Étape 2 n'a extrait que les champs d'en-tête).
- Chunking : heuristique par section (titres MAJUSCULES, ancres, articles
  numérotés) — fonctionne bien sur les factures/contrats/rapports générés,
  pas testé sur une mise en page réelle très différente.
